## What the night was for

The goal set before sleep: a management skill that fits all four work modes,
with **deterministic code for state query and management** so aiMark can drive
it, built to survive **real projects' existing code, data and doc structures**.

The single most useful thing done was checking that last clause **first**,

## The three findings that changed the plan

**1. `perry-task list` reported 3 tasks for a project with 41.**

`~/proj/gimegime-pmo` organizes its board by workstream — `## Open — 投资线`,
`## Open — 工程线 · phase #004`, `## Backbone` — with exactly one section named
`P2`. Tables of four and five columns instead of six. Ids in strikethrough.
Statuses in Chinese. One row whose first cell is prose. Reading only P0/P1/P2
found the one heading that happened to match, and two of the three "tasks" it
returned were rows from a `## ID prefixes` reference table.

**A front-end fed that payload shows the user confident nonsense**, which is
worse than showing nothing. Now 41 tasks, plus a `conformance` block naming the
1 unreadable row and the 17 statuses outside the enum.

**2. The write lock was polluting every consumer repo.** `?? .board.lock`,
untracked and unignored, in a real project the same night it shipped. Consumer
repos do not inherit Perry's `.gitignore`, and "each user adds an ignore rule"
is Perry pushing its bookkeeping onto them. Moved to the temp dir.

**3. A closed task's id was reissued** when `.perry/events.jsonl` was deleted —
a file the tool calls disposable while ID uniqueness depended on it. Found by
demonstrating where state lives, not by review.

## Corrections made mid-flight, recorded rather than smoothed

Four times, a check I had just written could not fail on the defect it named,
and mutation testing caught it rather than reading:

- the bootstrap guard skipped any line containing `**not**` — and the mutated
  line carried both the creation and the disclaimer
- the ownership check captured `[^.]*`, which stops inside `` `BOARD.md` ``
- the cross-lane guard matched the exact backticked path, so it saw
  `` `evidence/` `` and missed `` `evidence/<YYYY-MM>/retro.md` `` — the form
  every real instruction uses. Once corrected it immediately found a fifth stale
  instruction no reviewer had reported.
- `perry-goals` read `present` / `day` / `kr_total` with defaulted `getattr` on
  fields that do not exist on the parser dataclasses, so a live OKR reported
  `okr_present: false` inside a well-formed payload
