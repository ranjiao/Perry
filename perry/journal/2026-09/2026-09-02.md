## Decisions

- **ADR-013 — An ADR id is an address, and is never reissued** · `Architecture` · active · `decisions/ADR-013-adr-ids-are-never-reissued.md`

  Answers USER-909. `perry-decide` mints by `max()` over the ADR files on disk and writes no events, so deleting the highest-numbered ADR erases a number from the minter's only memory and the next mint hands it out again. Chosen: a durable high-water mark in `.perry/events.jsonl`, with `mint_id` taking `max(ADR files ∪ mint events)` — the same rule `perry-task` states as `minting_records`. `TASK-240` implements it.

  **Three measurements on `d49964e` reshaped the decision away from the recommendation recorded on the ask itself**, which was "(b) then (a)":

  1. Only the *highest* id reissues. Deleting a middle id leaves the gap permanent — mint ADR-001…005, `rm ADR-002`, next mint is `ADR-006`. So what was needed is a high-water mark, not an event surface on every command.
  2. Option (b), "refuse the delete", has nothing to refuse in: `perry-decide` has five commands — `bootstrap`, `new`, `supersede`, `status`, `list` — and no delete. An ADR leaves `decisions/` by a human `rm`. It could only ever have been documentation plus an after-the-fact detector.
  3. The cheap fix — a counter file beside the ADRs — is foreclosed by `tests/test_decide_writer.py:461` `ADR_ONLY`, which is `TASK-235`'s own deliverable. That left the event log as the only durable home, and `.perry/events.jsonl` is owned by `perry` rather than a lane in `schema/state-schema.json § claims[]`, so `decide` writing it is not a hand-off breach.

  Stated limit, in the ADR rather than glossed: deleting `.perry/events.jsonl` re-exposes reissue for ids whose files are also gone. The log is declared derived and disposable, so this is a bounded mitigation, not a guarantee.

  Checked before minting: `ADR-013` was already cited 11 times in the repository, and every one of them is inside a throwaway-project reproduction (`tests/test_decide_writer.py` fixtures, `TASK-235` evidence). None referred to this project's ADR-013, so minting satisfied no stale citation by accident.
