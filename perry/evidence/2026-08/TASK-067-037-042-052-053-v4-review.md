### Finding 1 — the sixth splitter, and the guard cannot see it

`viewer/parsers.py:208`, inside `read_conformance`:

```python
cells = [c.strip().strip("`") for c in m.group(1).split("|")]
```

That is a markdown **table-row** splitter — it skips the header row by name and
the separator by regex lookahead — in `viewer/parsers.py`, the read side of all
three frozen contracts, and it does not honour `\|`. Reproduced:

```
render_row      : | design/DESIGN-9 \| draft.md | 2 | 2026-08-18 | declare |
split_row       : ['design/DESIGN-9 | draft.md', '2', '2026-08-18', 'declare']
read_conformance: declarations {} · unreadable [(5, '| design/DESIGN-9 \| …')]
```

A row Perry's own writer rendered correctly reads back as **no declaration at
all**. That is this finding's own thesis, one file over.

`test_no_reader_carries_its_own_splitter` is green throughout, and cannot be
otherwise: it greps the literal substring `strip("|").split("|")` over a
**hardcoded list of eight files**. `viewer/parsers.py` *is* in the list — the
list is not what failed. The **spelling** is. And it is the same spelling that
already walked past this guard once: `bin/perry-explain`'s
`m.group(1).split("|")`, found by TASK-050's round 2, not by this test. Twice
now, the same shape.

The right guard already exists in this repo, in the test file next door.
`tests/test_one_header_rule.py § READERS` enumerates *everything* in `bin/`
plus `viewer/parsers.py` and says why in a comment — "not a curated list of
offenders … a NEW reader is caught too". TASK-067's splitter guard was never
brought up to it.

**Smallest fix.** Two lines:

1. `viewer/parsers.py:208` → `cells = [c.strip().strip("`") for c in T.split_row(...)]`
   (or route the row through `split_row` directly).
2. In `test_no_reader_carries_its_own_splitter`, replace the hardcoded tuple
   with `test_one_header_rule.READERS`'s enumeration and the literal substring
   with `re.compile(r'\.split\(\s*["\']\|["\']\s*\)')`. I ran that regex over
   `bin/`, `viewer/`, `templates/`, `setup/` and `packs/`: it returns exactly
   two hits — `parsers.py:208` (the defect) and `parsers.py:1365`
   (`phase.status … .split("|")[0]`, a **value** normalizer, legitimately its
   own rule under `test_one_header_rule`'s own stated doctrine, so allow-list
   it or narrow the regex to list comprehensions over a row).

### Finding 2 — the round-trip clause's test is a fig leaf, and the clause is not

I fuzzed `render_row` exhaustively over `{a, |, \, space, backtick}` to length
4, in 1- and 2-cell rows: **zero** single-line values reach the round-trip
clause. With the escape intact, no reachable production input can fail it.
`render_row([])` is unreachable too — every one of the 20 call sites builds
its list from a header or from a `split_row` result, and both are always ≥ 1
cell. So `test_an_empty_cell_list_is_refused` drives an input no caller can
produce, purely so mutation 3 has a colour.

I do **not** recommend deleting the clause: the criteria file requires it
verbatim ("stated as the round trip … `split_row(render_row(cells)) == cells`"),
and as a runtime assertion that the two functions stay inverses it is cheap and
correct. What should go is the **claim**. Mutation 3 was honestly reported as
green and then given a synthetic trigger; the table should read **10/11 red,
one clause unreachable-by-design**, and the test should be restated as the
property the criteria actually name — `split_row(render_row(c)) == [x.strip()
for x in c]` over a generated corpus — which is reachable and does go red when
the escape changes. This is a documentation defect, not a code one, and on its
own it would not fail the task. Finding 1 does.

duplication this task's spec is about."* It is **not small any more, because it

`TASK-067-finding.md`'s first acceptance criterion:

> A cell value that would not read back as itself is **refused at the writer**,
> naming the field and the character. **Not encoded, not stripped silently** —
> the user asked to store something the format cannot hold.

```

$ perry-goals commit --track ops --promise $'line one\n\nline two' --to Finance --by "within the track SLA"

# AMEND path — goes through bin/perry-goals § splice_cell
$ perry-goals commit --miss ops/7 --reason $'line one\n\nline two'

perry-goals: wrote OKR.md § Commitments — ops/7 → missed
| ops   | ops/7 | … | missed | oldest-first · line one  line two  |
```

`splice_cell` line 273 (and `append_cell` line 288) do
`.replace("\n", " ").replace("|", "\\|")` — encode-and-strip, silently, at
exit 0. `--close --discharged-by` reproduces identically. The user's paragraph
break is gone and nothing says so. This is TASK-067's finding, alive, in the
file TASK-037's spec specifically forbade putting a second copy in.

Four header-rule copies and five row-splitters have been found in this repo.
This is a **sixth writer-side copy**, and unlike the others it is not merely

**Smallest fix.** Move `cell_spans` / `splice_cell` / `append_cell` /

## 3 · TASK-042 — `commit` stops being prose · **PASS**

Criteria: `goals/reference/phases.md § commit <promise>`. Each claim run.

**Column resolution is table-local.** Verified on the Chinese fixture, whose


The value landed in `截止`; no column was widened, no header rewritten, every
other cell byte-identical. `column_spellings` asks "which header cell of *this*
table is `By when`" rather than "what does `截止` mean", which is the right
direction and the docstring says so.

**A hand edit is reconciled, never overwritten.** Verified end to end. Tool
writes `ops/7 → closed` (event `to: closed`); I hand-edit the file back to
`active`; next write refuses at rc=1 naming both values; `--accept-hand-edit`
proceeds and the event records **`from: "active"`** — the *file's* value, while
the log said `closed`. Exactly as specified.

**The exemption is a hole, and I got through it — but the criteria authorise
it.** `check_hand_edit` keys on the Id as it currently reads in the file, so a
hand edit that *also* renames the Id makes the row permanently exempt:

```
tool:  ops/7 → closed                      (log: to=closed)
hand:  Id ops/7 → ops/9, Status → active   (one edit, two cells)
tool:  commit --miss ops/9 --reason hidden
rc=0 — written, no refusal, no --accept-hand-edit
```

The identical Status edit *without* the rename is refused. So the reconcile
promise costs one extra cell to defeat. That said: `phases.md` states the
exemption explicitly and gives a good reason for it (every register alive today
predates the tool), and `logged_status`'s docstring argues the case honestly.
Judged against the written criteria this is conformant, so it does not fail the
task — but it is worth closing, and the data is already loaded. **Suggested
one-liner:** when an Id the log has minted is *absent* from the table, report
it. `ops/7` vanishing from the register while sitting in `events.jsonl` is
detectable with `commitment_events(events)` and nothing else, and it would make
the exemption safe without touching the pre-tool case at all.

Also verified: `perry-goals/list/2.0` did not move (`G.LIST_CONTRACT`, pinned by

**Smallest fix.** One test in `TestEveryWriterThatFilesARowReadsGroup`, whose

```python
def test_two_drains_leave_the_intake_table_intact(self):
    p = Project(tracks=self.TRACKS, board=self.WORKSTREAM)
    p.run("intake", "--title", "one", "--arrived", "2026-08-05")
    p.run("intake", "--title", "two", "--arrived", "2026-08-06")
    for n in ("1", "2"):
        code, out = p.run("route", n, "--track", "ops", "--group", self.HEADING)
        self.assertEqual(code, 0, out)
    sec = self.section_of(p, "Intake")
    self.assertRegex(sec, r"\n\|[\s:|-]+\|\s*\n", "the separator row was overwritten")
    self.assertEqual(sec.count("| one "), 1, "the request was duplicated")
    self.assertEqual(sec.count("routed →"), 2)
```
