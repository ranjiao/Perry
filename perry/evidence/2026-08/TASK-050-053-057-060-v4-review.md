## TASK-053 — FAIL

**Criterion.** The intake drain runs on a board with no `## P0`/`## P1`/`## P2`, and the drain leaves the board in a state a second drain can run from.

The `--group` half is delivered: the refusal lists the project's own headings, and passing one back files the row correctly. Verified on a copy of `~/proj/gimegime-pmo` (`route 1 --track ops --group "Open — 工程线 · phase #004 W24（流程层）"` → exit 0, row landed in the named section, `Arrived` carried). Guard liveness confirmed: replacing `target_section(...)` with `check_priority(args.priority or "P1"), ""` turns **7 tests red**.

**But the drain corrupts the board on exactly the shape the task is about.**

`Board.ensure_section` anchors `## Intake` at `next(... PRIORITY_RE["P0"] ...)` **or `len(self.lines)`** (`bin/perry-task:539-541`). On a board with no `## P0` — TASK-053's whole premise — `## Intake` is therefore appended at the **bottom**, below every section a row can land in. `cmd_route` then captures the intake row index `idx` at line 2591, calls `append_row` (which does `self.lines.insert(at, line)`) at 2652, and only afterwards writes `ctx["board"].lines[idx] = render_row(...)` at 2654. When the landing section is above `## Intake`, `at <= idx`, every later index shifts by one, and the outcome is written **onto the intake table's separator row**.

Fully tool-created reproduction — nothing hand-placed, Perry creates `## Intake` itself:

```
$ perry-task intake --title "do a thing"       --arrived 2026-08-10
$ perry-task intake --title "do another thing" --arrived 2026-08-11
## Intake
| Arrived | Request | Outcome |
|---|---|---|
| 2026-08-10 | do a thing | — |
| 2026-08-11 | do another thing | — |

$ perry-task route 1 --track ops --group "Open — workstream"     # exit 0
## Intake
| Arrived | Request | Outcome |
| 2026-08-10 | do a thing | routed → W-002 |     <- overwrote the separator
| 2026-08-10 | do a thing | — |                 <- the real row, still undischarged
| 2026-08-11 | do another thing | — |

$ perry-task route 1 --track ops --group "Open — workstream"
{ "refused": "`## Intake` has no table" }
```

Exit 0, no warning. The separator is gone, so `## Intake` is no longer a markdown table to `section_table` — the queue is bricked after one drain, and the request that was routed still reads as pending.

**The guard is blind, and it is blind on its own fixture.** `TestEveryWriterThatFilesARowReadsGroup.WORKSTREAM` has no `## P0`, so `intake` appends `## Intake` at the bottom and the fixture hits this path. I ran the guard's own `drained()` helper and printed the board it leaves:

```
route exit: 0   id: TECH-002
the guard's assertion ('routed → TECH-002' in board): True
## Intake
| Arrived | Request | Outcome |
| 2026-08-05 | 客户要对账 | routed → TECH-002 |
| 2026-08-05 | 客户要对账 | — |
separator rows left in ## Intake: 0
intake rows still showing Outcome '—': 1
```

`test_the_intake_row_is_discharged_by_a_grouped_route` asserts only that the string `routed → <id>` appears *somewhere* on the board. It does — on the line that used to be the separator. All five tests pass on a corrupted board.

**Smallest change that would pass.** In `cmd_route`, write the intake row back **before** `append_row` inserts (`widen_target_section` edits lines in place and does not shift indices, so it may stay where it is); or keep the order and adjust: `if at <= idx: idx += 1`. Then add to the guard the assertion that makes it non-blind — the `## Intake` table still has its separator row and the routed request no longer shows Outcome `—`.

## TASK-050 — FAIL

**Criterion (as posed): is there any remaining place in `bin/` or `viewer/` that normalizes a header cell by a second rule?** Yes — **three sites in two files**, neither of which imports `squash`:

- `bin/perry-state:123` — `cells[0].lower() != "term"`, the header skip in `load_packs`
- `bin/perry-state:183-197` — `cells_of()` + `low = [c.lower() ...]`, the header resolution in `parse_tracks`
- `bin/perry-diagnose:1301-1302` — the same pair in `md_table`, which `scan_work_modes` runs over the **user's own `BOARD.md` and `OKR.md`**

The rule they use is ``c.strip("*` ").lower()``. It agrees with `squash` on wholly-wrapped cells (`**Track**`, `` `Track` ``) and disagrees whenever decoration or whitespace is internal:

| header cell | `squash` | ``strip("*` ").lower()`` |
|---|---|---|
| `**Default** rung` | `default rung` | `default** rung` |
| `Default **rung**` | `default rung` | `default **rung` |
| `Next  action` | `next action` | `next  action` |
| `By  when` | `by when` | `by  when` |

Reproduced as behaviour, not as string algebra — `perry-state.parse_tracks` on a Tracks table whose header reads `| Track | Mode | **Default** rung |`:

```
at e866ca8:   {'track': 'ops', 'mode': 'queue', 'default_rung': ''}
with the fix: {'track': 'ops', 'mode': 'queue', 'default_rung': 'V2'}
```

The track's declared verification floor vanishes silently, and `bin/perry-task` reuses this very parser (`perry_state().parse_tracks`, line 3302), so the loss propagates into every rung default. `perry-diagnose` is worse-exposed: it is the tool that grades a project's board shape, and it reads that board by the weaker rule while `viewer/parsers.py` and `bin/perry-task` read it by `squash`.

The delivered work is real — `parsers.py` importing `squash` closes the reader/writer split on the board, risk, task and goals tables, and I confirmed the four exits (`risk-add` / `perry-state` / `perry-lint` / `risk-migrate`) now agree. What fails is the **category**, and specifically the claim written into `viewer/tables.py:143` that the question *"is this cell that column?"* now *"has exactly one answer in this repository."* It has two.

**On the `parse_frequency` exclusion — the builder is right, but for a different reason than given.** `viewer/parsers.py:788` normalizes a **Frequency value cell**, not a header cell: it answers "what does this cell say", not "which column is this". It is also the sole reader of that cell (`bin/perry-task:1955` and `bin/perry-state:405` both call it), so no reader/writer disagreement is possible, and stripping `_` there is correct for `_ad hoc_`. Not the same defect renamed. The character class is a red herring; the scope is the answer.

**Smallest change that would pass.** Import `squash` in `bin/perry-state` and `bin/perry-diagnose` and use it for the three *header-key* lists only — `low = [squash(c) for c in cells]` in `parse_tracks` and `md_table`, and `squash(cells[0]) != "term"` in `load_packs`. The data cells keep ``strip("*` ")``, which is a different intent. I applied exactly this: **1006 tests, OK** — which is also the point, since nothing in the suite covers the difference either way.

## TASK-060 — PASS

**Criteria.** `--prefix` wins; absent it, the board's family is adopted only when the board has exactly one; the threshold is defended rather than arbitrary.

I counted the families myself on the gimegime-pmo copy via `board_id_prefixes` — **36**, confirmed. One correction to the reasoning, which strengthens it rather than weakening it: `_ID_SHAPE` splits at the *last* hyphen, so slug-tailed ids tokenize into families of their own (`TECH-cash-no-manual`, `DATA-BARS-CACHE-NO-END`). The board's own `## ID prefixes (canonical)` section declares roughly 17. Either number is ≫ 1, so the conclusion stands — and the over-split fails *safe*, toward `TASK`, never toward a wrong claim.

Behaviour, verified end-to-end:

| board | flags | minted |
|---|---|---|
| `AIM-<n>, AIM-<n+k>, AIM-<n+k>` | — | `AIM-<n+k>` |
| `AIM-<n>, AIM-<n+k>` | `--prefix AIM` | `AIM-<n+k>` |
| `AIM-<n>, OPS-001` | — | `TASK-001` |
| `AIM-alpha, AIM-beta` | — | `TASK-001` |
| `USER-001, USER-002` | — | `TASK-001` |
| `AIM-<n>` | `--prefix USER` | refused — reserved family |
| `AIM-<n>` | `--prefix AIM-<n+k>` | refused — "pass `AIM`, not `AIM-<n+k>`" |
| `AIM-<n>` | `--prefix ARCH-V2` | `ARCH-V2-<n>` |

Guard liveness: `len(families) == 1` → `>= 1` turns `test_a_board_with_several_families_is_not_guessed_at` red; disabling the `--prefix` branch turns **6** red, including `test_route_takes_prefix_too`.

**Is "exactly one" arbitrary?** No — it is the only threshold at which the adoption is not a guess, and the asymmetry justifies it: a wrong-family id is a permanent, non-withdrawable claim about a workstream, while a foreign-looking `TASK-001` claims nothing. `--prefix` is documented at `work/reference/subcommands.md:468-478` and is reachable by a front end.

**Scoped observation, not a defect.** A board of `AIM-<n> … AIM-<n+k>` **plus the stray `TASK-001` Perry already minted onto it** now has two families, so the default returns `TASK-002` — the fix cannot heal by default the board it was written for. aiMark's board is in exactly that state. `--prefix AIM` is the documented answer and TASK-060 asked for "default to the prefix the board already uses, **or** accept `--prefix`". Both shipped. Worth a line in `subcommands.md`.

## On the builder's own flag: M10 / M11 "green by construction"

**The claim is true today, and I verified it directly rather than taking it.** Scanning all **172** declared spellings in `schema/state-schema.json § i18n` (`headings`, `fields`, `columns`, canonical + every localized form): **0 contain a backtick or asterisk**, and `squash(v) == v.strip().lower()` for **all 172**. So squashing the glossary keys is observationally identical to lowering them.

Confirmed by running the mutation: `_column_index`'s `squash(s)` → `s.strip().lower()` in `viewer/parsers.py`, plus both `squash` calls in `perry-task._build_column_maps` → `.strip().lower()`. Result: **1006 tests, OK.** These are null mutations, not blind guards — the builder's characterization is honest.

**Does `assertIs(P.squash, PT.squash)` suffice? No, and neither does anything else.** It pins that the reader and the writer share one function object — a genuine and well-chosen guard, and the corpus tests would indeed keep passing against a re-inlined copy without it. But the glossary path is a different question, and nothing pins it:

- The corpus tests assert **agreement**, so mutating the shared `squash` keeps both sides wrong together and they stay green. (Mutating `squash` itself *is* caught, but by the four-exit behavioural tests — `test_perry_state_counts_a_risk_under_a_decorated_header` and siblings — not by the corpus.)
- **No test asserts the property that makes M10/M11 null.** Grepped: nothing in `tests/` checks that declared spellings are decoration-free. The day someone adds `**状态**` or a double-spaced spelling to the glossary, the invariant silently stops holding and no test notices.

**Smallest change:** one assertion in `tests/test_i18n.py` — for every declared spelling `v` in `i18n.{headings,fields,columns}`, `squash(v) == v.strip().lower()`. It costs three lines, it passes today, and it converts "green by construction" into "green and pinned": a future decorated spelling then fires a test that names the glossary-normalization path instead of leaving it to a later reviewer to re-derive.
