## Two boundaries the agent named rather than buried

1. **`--strict` narrows tool-wide.** It no longer promotes `NS-01`; it still
   promotes every other warning. The authority is DESIGN-002 § 9, appended at
   lock: *"A collision never sets a non-zero exit."* The first agent read that
   as scoped to `--claims`; this one argues the reasoning is about the
   **finding** — decision #2 left no per-path opt-out, so a user deliberately
   keeping one file in a claimed folder would otherwise have permanently red CI
   with no way to accept it, which DESIGN-002 rejects by name in the same breath
   that it pins `NS-01` at `warn`. "A severity a flag can escape is not really
   `warn`." Both directions are pinned: `NS-01` alone → rc 0 under `--strict`;
   any other warning alongside it → rc 1. **Still a reviewer's call**, because
   it changes what a flag means everywhere, not just what one finding does.
2. **P4 is half-closed.** DESIGN-002 § P4 says the fix is "a distinct finding
   **rather than** a parse failure". The deliverables asked only for the
   finding, so a foreign `design/proposal.md` now gets `NS-01` *and* is still
   reported as malformed Perry state, and those parse errors still exit 1.
   Suppressing `check_file` over foreign files in a claimed directory reaches
   ADR-004's per-file conformance gate — a change of another size. Pinned by
   `TestTheParseFindingsStillCoexist` so the remaining half is visible rather
   than assumed done.
