## 1 按负责人存放，按用途阅读

既有领域路径保持；内部／跨角色使用通过主要读者与角色入口区分，不复制内部版和外部版。角色入口按七种用途分组，元信息沿[正式规范](documentation-standard.md)。

| 路径 | 维护者与内容 |
| --- | --- |
| README.md、AGENTS.md、todo.md、docs/README.md | 策划；项目入口、权限、全局任务与总导航 |
| docs/design/ | 策划；玩法专业资料、人物／武器等权威总表和测试设计 |
| docs/decisions/ | 策划；用户决策／授权与待决，保留原始依据 |
| docs/research/ | 策划；长期参考资料及来源／局限 |
| docs/discussions/ | 策划；原始讨论与修正依据，属于历史证据，不是当前规则 |
| docs/production/ | 策划；共享规范／模板、对外交接与试玩执行计划 |
| docs/production/evidence/ | 策划；可安全迁移的独立审查／整理证据及本轮清单 |
| docs/tech/、docs/qa/ | 程序；组件／架构／接口／工具指南、版本验证与原始证据 |
| docs/art/ | 美术；风格与经验、资产分类视图、制作／接入交付、预览指南与证据 |
| docs/archive/<领域>/<年份>/ | 原角色；独特历史正文，根归档索引由策划汇总 |
| assets/source、exports、previews、concepts、manifest.md | 美术；源、导出、预览、概念与唯一素材登记 |
| game/、tests/、程序工具目录 | 程序；运行副本、代码与验证；本轮整理不改运行内容 |

目录不存在时按实际内容创建；不批量造七套空目录。旧专业源、接口和程序读取路径先原地分类；长文可为不同读者分离使用指南，不复制参数或资产登记。

## 2 任务工作区

有实际中间记录时，放本角色领域work/<task-id>.md，例如docs/design/work/cs-077.md、docs/tech/work/dev-nnn.md、docs/art/work/art-nnn.md；文件名小写。工作稿必须从所属任务可达，任务ID仍按CS／DEV／ART各自维护，不新造编号系统。

任务结束时将结论提炼进长期源，必要复现／失败依据转证据，其余纯重复稿可清理。没有需要持续维护的临时稿就不建占位文件；已经正式交付的规则不会因叫“提案”而变成临时垃圾。

## 3 索引与固定名称

每个角色README按我的工作、长期资料、对象总表、协作接口、使用指南、验证／历史分组；项目治理引用总导航。小类别可在同页分节，索引只写用途／边界与链接，不重抄当前任务状态或参数。

人物／武器／敌人／能力／地图／Perk仍用现有固定源；characters.md集中全员人物，weapons.md集中武器。组件总表和资产manifest也不改编号或派生第二份总账。一个对象可以引用多件资产，设计ID、资产ID、运行版本分开。

当前文件原地修订，英文路径稳定；一次性证据用YYYY-MM-DD-主题-review|delivery|validation.md。报告目录内不必再套同名版本目录；多份原始JSON可与报告相邻集中。程序真实日志／截图／固定检查输入依赖未解除前原位保留。

## 4 迁移与权限

迁移前核对文档、图片、脚本、配置、快照和只读角色引用；登记原路径／后继／理由／前后SHA256。迁后修相对链接、直接索引与任务。原始快照内旧路径保留其历史语义，不能改成“当时已采用新路径”。

被其他角色或工具绑定的文件可原位维护，在用途索引注明原因；不为目录整齐强搬，也不随意删代码、模型、源资产、测试或许可。未跟踪文件先保存实际内容，不假定Git可恢复。归档沿原领域权限，不设长期“跳转森林”。

根todo由策划维护全局阶段／CS交付；角色todo由各角色维护内部任务。需要跨角色改引用时交清单，按明确授权或由原维护者修改。整理过程保护其他会话WIP，不自动提交、回退、清理或跨会话派遣。

## 5 运行资产边界

3D源仍在assets/source，导出在assets/exports，运行副本在game/assets；唯一源／许可在assets/manifest，运行采用在程序manifest。角色、武器、物品、特效和地图按原素材接口及ADR，不借文档迁移修改尺寸、碰撞、命中或导航。

文档元信息补齐与链接通过只构成静态证据；引擎、同机、LAN、设备、性能、真人与用户确认仍分层记录。默认从当前用途入口读，archive／evidence／work仅按历史依据或具体任务进入。
