## 本轮推荐取舍与理由

| 取舍 | 推荐方案与理由 |
| --- | --- |
| 弹药压力 | 无限备弹、保留弹匣；把压力放在换弹窗口，避免新手因打空总量而长期失去参与能力 |
| 多人时长 | 人越多每批越多，保留请求节奏；增加同屏合作压力，不靠额外批次数拖长一局 |
| 同步清怪与倒地 | 所有波次先认清波；保住已经赢下的一波，规则容易理解。后续仍未清波的团灭照常失败 |
| 自救额度 | 每局一次，波间返场不补次数；整备复活与个人自救消耗分开，避免不知情地每波刷新 |
| 出兵保证 | 域外隐藏集结＋合法备用路；守门是允许的战术，不要求玩家主动退让；坏配置有界报错退回联调 |

## CS-051 程序：状态裁决与每局自救

**问题出处：**审查06／07／08；只读发现`wave_mode._reward`重置自救标志，所有波次清场优先已存在，但未与设计／完整伤害处理顺序统一；无行动者停刷尚待补齐。

推荐同一步顺序：完成该步合法伤害、死亡收集、救援／到期事件→判断待刷／存活是否都为0→清波或继续→检查行动／自救／失败宽限→只有允许继续战斗才处理新的出兵。具体函数拆分由程序决定，不能让有状态的客户端各自裁决。

| 案例 | 操作／输入 | 必须结果 |
| --- | --- | --- |
| S01 跨波自救 | 单人第1波用自救，清波；第2波再次倒地且仍有怪 | 波间可补满／返场，但资格仍已用；不能再自动起身，按失败宽限处理 |
| S02 重连与新局 | 自救后掉线重连；胜负后由房主新开局 | 重连保留消耗；只有新局重置。记录局ID、身份与标志，不借换连接领第二次 |
| S03 合作转单人 | 曾有两名人类同局，另一人退出；剩余玩家倒地 | 本局不能重新获得单人自救；掉线／旁观不伪造新身份或新局 |
| S04 前两波同一步清场 | 分别在波1／2使最后敌人死亡、最后玩家倒地；无自救 | 有限兵力确已全出且全灭则进入一次15秒整备，复活返场；自救消耗不重置。不判失败 |
| S05 最终波同一步清场 | 波3重复S04；加入重复死亡／重复清波事件 | 只提交一次胜利，不发最终整备奖励；重复事件不反转、不二次奖励 |
| S06 未清场团灭 | 留1敌或待刷>0，全员倒地，无可用自救 | 不清波、不先发资源；无人恢复则2秒宽限后一次失败。合法自救时等自救，不能2秒提前判负 |
| S07 同步步完整性 | 用该模式合法伤害／救援事件构造清场及致命伤，交换事件入队顺序；在宽限终点重复 | 房主该步收集完后结果相同；不得在伤害尚未处理完时锁定相反结果。若保留调试弹体，另测其延迟命中，不要求新增火箭 |
| S08 无行动者停刷 | 待刷已到时，全员倒地进入5秒自救等待／2秒宽限 | 不新生成；原预告取消而待刷／当前批余量保留。恢复后重新预告≥1.5秒且距上次生成≥5秒，不追补爆发 |
| S09 身份与奖励 | 波间同身份反复断线／重连、晚加入；终局后重复输入 | 每身份每波只领一次奖励；恢复当前状态与自救资格，不退回绿地。不允许客户端重开全队 |

交付：反例复现或说明当前已满足、改动清单、单人自动测试／日志及重开回归、同版本本机多进程和真实两机证据分别登记；没有设备时明确留待验，不代写通过。

## CS-052 程序：M1武器采用与HUD同步

仅M1主武器使用无限备弹＋正常弹匣；有限模式通过配置保留。H1／H3采用§1基础四项及§6射程衰减，其他既有手感按武器§9继承，不顺便重构所有枪型。程序在交付写“字段／本轮目标来源／当前有效值／是否改变”，导出有效配置及哈希，明确没有采用哪些产品候选字段。

| 案例 | 必须结果 |
| --- | --- |
| W01 连续射击／空匣 | 两枪各射超过旧有限备用预算；始终可正常换弹，但空匣不能射击、不免费补当前匣；首发／连射／换弹时序符合采用值 |
| W02 取消／恢复 | 半匣换弹中切换或断线，重连保留当前匣；完成换弹只装到容量，取消不发子弹；非法负数库存不泄漏到有限模式 |
| W03 整备／终局 | 前两波各身份一次补满常驻匣与生命；最终波直接结算，不显示“已补满”，不重置自救消耗 |
| W04 距离与遮挡 | 分别验证两枪满伤点、衰减中点、衰减终点、硬上限内外；中点倍率0.825、硬上限外不伤；枪口贴墙不穿墙。20米无弱点时A分别3／4发；远距测试在测试场，不扩大CBD |
| W05 头部与旧模式 | M1保留H1×1.75／H3×1.5继承口径；旧有限任务／测试配置仍按各自资源规则，M1模式切换不会污染旧模式 |
| U01 权限与提示 | 房主可开始／重开，客户显示等待房主；自救只在权威资格有效时显示进度，用尽／合作转单人不显示虚假自救 |
| U02 数量与版本 | 弹药显示匣／∞；剩余敌人=在场存活＋待刷，部分批次不漏计；暂停配置异常与普通整备／失败明确区分，客户端结果一致 |

2026-10-20核对：[程序入口](../tech/README.md)与[程序todo](../tech/todo.md)已区分当前M1与旧P0／500米历史，上述入口清理不再作为未完成项；CS-051／052玩法验收仍独立待交。程序README／采用身份／QA随实际交付同步。[美术当前UI素材v0.5](../art/ui-m1-kit-v01.md)已独立交付、未接Godot；接入时仍以策划HUD为规则输入，不用素材示例读数代替权威状态。导演不代改角色文件。

## CS-034／033 CBD来敌与空间补验收

| 案例 | 必须结果 |
| --- | --- |
| G01 1～4人枚举 | 总量／上限按源表，每批2／3／4／5只、6／9／12个基础请求；波内锁N，晚加入／掉线下波生效；分批受阻不丢余量、不突破总量／上限 |
| G02 守门正常玩法 | 单人贴门、四人分守三门／看向候选点；正式H均在玩家域外、不可达、有遮挡且距合法玩家位≥15米。人不必退让才能继续来敌，正常占位不触发无限停刷 |
| G03 路线与预告 | H→E→战区可走；备用换E重做≥1.5秒预告；首侧潮从E显形比主潮晚≥10秒；有预警不能代替真实遮挡 |
| G04 无合法H注入 | 故意使全部H失效，1秒重试；连续10秒有效受阻进入可返回准备的配置异常暂停，不判胜负／奖励，不暗刷／传送。自救等待、已在场满额不计该异常计时；合法恢复后计时归零 |
| G05 卡路与边界 | 遮挡不堵死双向路线；大批队形不能叠穿；玩家边界不封敌人通路。不得将活怪无预告搬入镜头；未修复卡路不静默记击杀或发奖励 |

空间交付须列正式H／E、导航域、遮挡件唯一实例ID、距离／视线验证和同版地图哈希；旧H不再有生成资格。若现有库无法形成合法域外H，提交最小点位／摆放偏差供策划调整；本单不批准盲猜坐标、移地标或重做全城。
