## 1 目标、输入与边界

本轮将任务工作稿、长期专业资料、对象总表、接口／交付、使用指南、验证证据与项目治理分清，内部／外部通过读者和入口组织。主维护角色与现有辖区不变，不复制两套正文，不代报已有玩法或素材通过。

唯一规范输入为[文档用途规范](documentation-standard.md)、[目录规则](project-structure.md)和[模板](templates/README.md)。[策划入口](../design/README.md)、[证据区](evidence/README.md)及[本轮报告](evidence/2026-10-22-planner-documentation-review.md)提供已整理示例；阶段和任务只见[根todo](../../todo.md)。

CS-055／056是第一批历史整理，不重新标为未完成；原交接已[留档](../archive/production/2026/documentation-handoff-before-purpose-classification.md)。本轮新增CS-078／079，各角色自行拆DEV／ART并维护本地todo，策划沿CS-080复核。

## 2 两角色共同交付

| 交付 | 必须包含 |
| --- | --- |
| 当前文档用途清单 | 每份文档的主要用途、主要读者、主维护者、维护方式、入口与处置；当前与历史分开 |
| 角色阅读入口 | 我的工作、长期资料、对象总表、协作接口、使用指南、验证／历史；无内容不造空目录或假正文 |
| 工作稿结束处理 | 每任务尽量一份记录；列有效结论回填处、保留证据和可删除重复稿；不把许可／失败样本当临时垃圾 |
| 当前元信息 | 补用途／读者和维护方式；沿已有ID、负责人、范围、依据与生命周期，不改成“全部已确认” |
| 处置清单与依赖 | 原路径→当前位置／后继、原因、前后指纹、入链／图片／脚本／配置消费者；固定输入不强搬 |
| 整理证据 | 各角色一份汇总报告，写实际检查、未完成项及需要策划修的只读入链，不为每次微调另造报告 |

整理只改自己辖区和自有归档。源码、素材、导出、运行manifest中的采用值、模型、测试原始数据不因分类随意搬删；未跟踪文件先保存内容。旧JSON／构建快照保留原时点路径和SHA，不伪造历史。

## 3 CS-078 程序

| 部分 | 交付与验收 |
| --- | --- |
| 内部专业资料 | 组件、架构、状态与恢复面向程序维护；components保留唯一总表，真实代码／配置是实际行为源 |
| 对外接口 | 素材接入、人物／武器／UI工具数据等接口标清提供者、使用者、版本、失败／兼容与退回条件；不复制美术源登记 |
| 测试场指南 | 从现有combat-lab综合说明提炼策划／美术可操作的指南：启动、分类、布置／确认、测量、重置／停止、报告与已知缺口；实现原理留专业资料 |
| HUD／UI工具指南 | 面向美术／策划说明实际编辑器的启动、编辑、保存／加载／撤销、配置产物、运行回读和失败恢复；核对实际能力，不把结构稿当可用功能 |
| QA与历史 | 被测版本／环境、原始日志、通过／失败／未测保持；既有固定路径与构建检查逐字节绑定的记录原位列例外，不为目录改历史输出 |
| 当前构建与索引 | 仍只有一个当前采用入口，指南引用它；源码／旧ZIP、展示样件／正式运行、同机／真实LAN／设备明确分开 |

程序不改策划／美术正文或根todo；需要对方改链接时提交路径与消费者清单。指南中的步骤须按实际工具核对，未运行明确标未验证；不以编写指南为由安装依赖或改变工具行为。

## 4 CS-079 美术

| 部分 | 交付与验收 |
| --- | --- |
| 内部专业资料 | 风格、制作流程与可复用经验持续维护；任务过程与失败证据分开，不能每份交付报告都升级为新的制作规范 |
| 对象总表 | assets/manifest保持唯一资产源／许可／导出登记；人物、武器、环境等类别页与画廊只引用，不复制第二份总账 |
| 对外交付 | 程序需要的单位／轴向、结构、骨架／挂点、材质、命名、版本搭配、检查与退回条件可直接找到；设计参数引用策划源 |
| 选择与预览指南 | 为策划／程序提供当前素材怎样选、预览／审阅怎样打开、哪份是源与导出、如何提交退回问题的说明；资产路径台账仍回manifest |
| 图组与历史 | 认可范围、原件／修订、独立检查／实际接入分开；失败样本、许可、提示词／来源与模型不随文档迁移丢失 |
| 入口与使用者 | 人物／敌人／武器等分类继续可达；另列程序可直接用的交付／预览指南，不要求读者先翻整段制作流水 |

美术不改game、程序说明、策划规则或根todo；现有发布器和固定引用尚未迁移时标保留输入，先登记例外。画廊可读与模型／游戏验收分开。

## 5 CS-080 统一验收

| 案例 | 检查 | 通过条件 |
| --- | --- | --- |
| U01 找文档 | 从总导航进入角色首页 | 能区分工作稿、长期源、总表、接口、指南与证据；不靠聊天或时间戳猜当前源 |
| U02 唯一源 | 抽人物／武器／素材／组件与一份指南 | 正文／参数／台账各有维护源，跨角色引用同源；没有内部版／外部版同步负担 |
| U03 生命周期 | 查工作稿结束和历史报告 | 有结论去向，独特证据保留，纯重复可清；旧证据不冒充当前实现 |
| U04 使用者操作 | 按测试场、编辑器或素材预览指南走一次 | 前置、操作、预期、产物、恢复和限制可执行；实际运行与未验证准确标注 |
| U05 迁移安全 | 查移动／删除、入链、图片及工具依赖 | 无新增断链、丢失许可或被重写的原始快照；例外有消费者、责任与后续任务 |
| U06 辖区与收尾 | 对照改动／本地todo／报告 | 未改他人WIP或玩法，索引与清单可达，静态／运行／用户确认分层 |

角色完成后由策划汇总根todo与受影响总入口；不自动跨会话发消息、代领或代报角色通过。整理完成不扩大M1或新增素材／代码制作授权。
