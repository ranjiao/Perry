# Dispatch preflight

The item/spec, dependencies, role if declared, project hook and executor matrix
are gates, not optional context. See `dispatch.md` and `kernel.md`.

Use the root config's selected/present packs before running an optional pack route.
Explain/help never reads project state just to determine pack eligibility. An
explicit project requirement still applies even when the optional pack is off.
For eligible software-ops Python code or governing-target work read the architecture
and apply real pre-edit/delivery checkpoints. For prose-only or unsupported-language
work record `not applicable` with the concrete reason; never certify TypeScript
or runtime behavior using Python facts. Choose scope from the written spec rather
than inferring a license to edit every linked module.

Classify high-stakes scope against the hook/role union. A previous scope authorization
covers actions it actually named, not publication or target edits absent from it.
A pinned executor must be supported on the active host. Preserve checkout ownership
and do not silently reroute a manually delegated task into automated execution.

## 0 · Whether to dispatch at all

Decide from the selected scope, written criteria, dependencies, ownership, active
host and actual authorization. Refuse an incompatible executor or missing gate;
manual delegation is a separate procedure, not an automatic fallback.
