# Queue work

A queue services incoming requests and recurring obligations. Agree priority,
owner, response expectations, consequences, review interval and verification
before accepting a request. There is no universal response-time default and no
mode-specific native command. Inspect the applied template and represent work as
tasks using its declared track/priority fields. Do not create legacy intake,
cadence or SLA registers.

Incoming requests are proposals until triaged. Resolve duplicate identities and
existing blockers with native queries; do not infer attribution from names.
Use asks for missing human answers and risks for unresolved concerns. Recurring
obligations stay in the agreed goals/work narrative; create the next concrete
task through the ordinary task procedure when authorized. Never invent a timer,
cron job, next-due computation or hidden writer.

At each review, page through the selected queue and relevant events, show exact
counts, unresolved dependencies and age source/units. State changes have event
times; unknown arrival/deadline facts remain unknown. Compare declared service
expectations with actual evidence, and surface breaches with consequences and a
next action. A warning does not authorize dropping requests or changing promises.

Verification follows the actual consequence and written criterion, with
independent review/human signoff where required. Follow
`reference/operating-rules.md`; legacy mode/SLA regex checks are retired, never fabricated current passes. Retain outstanding obligations in
the handoff and follow `reference/next.md` after writes.
