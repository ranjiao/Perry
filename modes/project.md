# Project work

Project work delivers a bounded outcome. Goals owns objectives, KRs and phase
intent; work owns task execution. Read the owning lane before mutation and use
`$PERRY_HOME/reference/kernel.md` for native state. Do not create a mode-specific state
store, journal, board or markdown-derived current status.

Before starting, identify a deliverable, written falsifiable acceptance criteria,
owner, dependencies and verification level. V3 is the ordinary reproducible-run
starting point; higher project/track requirements apply. Actual high-stakes
consequences require the applicable human decision and V5 when required. A mode
default never waives a project safety gate.

Read complete native task queries for counts and dependencies. Verify actual
artifacts and tests at closure, attach the evidence and report limits. V4 needs
independent fresh-context review; V5 needs the actual named human's signoff.
Follow `reference/operating-rules.md`, `work/reference/task-close.md` and the
shared closing step in `reference/next.md`.
